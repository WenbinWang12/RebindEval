## Dataset summary

VarTrace is a synthetic, rule-generated benchmark for **in-context variable tracing with renamable variables**.
A problem lists assignments over named variables (constants, copies, additions of a constant, sums and differences,
all modulo 23) in some premise order and asks for the value of one variable. The gold solution evaluates the
dependency closure of the queried variable in topological order, one line per variable, and ends with the answer.

The dataset separates the *computation* of a problem from its *surface*. The same computation can be shown under
different variable names and premise orders, so a model can be tested on computations it was trained on under name
assignments it has never seen. The data were built to study whether fine-tuning optimizers differ in how strongly
the learned computation is tied to the names used in training.

Everything is generated by a deterministic, pure-Python program. No human-written text and no personal data are
included.

## Example

```text
Variables (arithmetic modulo 23):
ros = 8.
ged = nir + ros.
nir = 9.
ruf = ged - nir.
Question: What is the value of ruf?
Solution:
```

Target:

```text
 nir = 9. ros = 8. ged = nir + ros = 9 + 8 = 17. ruf = ged - nir = 17 - 9 = 8.
Answer: 8
```

## Supported tasks

- **Text generation / step-by-step reasoning.** Given `prompt`, generate `target` (the full derivation and the final
  answer).
- **Scoring.** Three scores are used with this dataset:
  - *exact match*: the generated solution equals `target`;
  - *valid derivation*: the final answer is correct and every written line is a true statement about the problem;
  - *final answer*: the number after `Answer:` equals `answer`.

## Dataset structure

### Terminology

| term | meaning |
|---|---|
| family | a dependency template over variable slots. There are 16 families (`vt00` to `vt15`): query depth 2 to 5, four shapes per depth. |
| parent | a family with its constants fixed. 256 training parents and 64 development parents per family. |
| surface | a name map (slot to variable name) together with a premise order. |
| variant | a parent shown under one surface. Every training parent has four variants (`variant_id` 0 to 3). |
| tier | `family index mod 4`. Each tier holds one family of every depth. |
| level | the number of training exposures a family receives in a schedule: 10,240, 512, 128 or 32. |

Training surfaces: each family has 8 name maps and 8 premise orders. Variant `v` of parent `p` uses name map
`(a_p + 2v) mod 8` and order `(b_p + 3v) mod 8`, with hash-balanced offsets `a_p`, `b_p`, so a parent is seen under
four different name maps and four different orders.

### Configurations and splits

| config | split | file | rows | content |
|---|---|---|---|---|
| `default` | `train` | `data/train.jsonl` | 16,384 | 16 families x 256 parents x 4 variants |
| `default` | `validation` | `data/dev_monitor.jsonl` | 64 | development parents on a seen surface, used to monitor the loss during training |
| `probes` | `M` | `probes/M.jsonl` | 256 | **memorized** items: training rows (the first 16 parents of every nested subset with their first trained variant) |
| `probes` | `G1` | `probes/G1.jsonl` | 256 | **new problems, seen surface**: 16 development parents per family under a training name map and order |
| `probes` | `G2` | `probes/G2.jsonl` | 768 | **new problems, new names**: the G1 parents and premise order under six held-out name maps |
| `counterfactual` | `test` | `probes/CF.jsonl` | 256 | every M row with one constant on the query path changed so that the answer changes |
| `selection` | `test` | `probes/S.jsonl` | 512 | panel for hyperparameter selection: 16 other development parents per family under two held-out name maps (`namex`: seen order, `bothx`: held-out order) |
| `schedules` | `k<r>_s<seed>` | `schedules/schedule_k<r>_s<seed>.jsonl` | 43,648 each | training order for rotation `r` (0 to 3) and order seed (20261021, 20261022, 20261023) |

Held-out name maps use the training names of the family, but no slot receives a name that it had in any training
map. The name maps of the selection panel and of G2 are disjoint, so G2 is not used for any selection.

### Training schedules

A model is not trained on `train.jsonl` in file order. A schedule lists 43,648 training events (682 optimizer steps
of 64 events). In rotation `k`, a family of tier `t` receives `LEVELS[(t + k) mod 4]` exposures with
`LEVELS = [10240, 512, 128, 32]`, so over the four rotations every family is seen at every frequency level.
Families at a level below 256 use the first parents of a fixed per-family hash order (nested subsets); the top
level repeats all 256 parents 40 times. Events are shuffled with the order seed; the variants of a parent rotate in
order of appearance.

Each schedule row refers to a training row by `id`.

### Data fields

Common fields (`default`, `probes`, `counterfactual`, `selection`):

| field | type | description |
|---|---|---|
| `id` | string | unique row identifier |
| `family_id` | string | `vt00` to `vt15` |
| `parent_id` | string | family and parent, e.g. `vt00-p000` |
| `variant_id` | int | index of the surface variant of the parent |
| `depth` | int | depth of the queried variable in the dependency graph (2 to 5) |
| `shape` | int | shape of the dependency template within its depth (0 to 3) |
| `tier` | int | `family index mod 4` |
| `condition` | string | `train`, `seen`, `name`, `namex`, `bothx` or `counterfactual` |
| `prompt` | string | problem text, ending with `Solution:` |
| `target` | string | gold solution: one line per variable of the dependency closure, then `Answer: <value>` |
| `answer` | int | value of the queried variable (0 to 22) |
| `gold_lines` | list | `[variable, solution line, value]` for every line of the gold solution |
| `all_values` | dict | value of every variable of the problem |
| `name_mapping_index` | int | index of the name map |
| `name_mapping_sha256` | string | hash of the name map |
| `order_index` | int | index of the premise order |
| `order_signature_sha256` | string | hash of the premise order |

Additional fields:

| field | where | description |
|---|---|---|
| `probe`, `probe_unit` | probes, counterfactual, selection | probe name and the unit used for unit-level averaging |
| `cf_slot` | counterfactual | slot whose constant was changed |
| `trained_answer`, `trained_values` | counterfactual | answer and values of the unchanged training problem |
| `selection_condition` | selection | `namex` or `bothx` |

Schedule fields: `position` (event index), `id`, `parent_id`, `family_id`, `variant_id`, `tier`, `level`
(index of the frequency level of the family in this rotation), `family_exposures`, `parent_occurrence_index`,
`name_mapping_sha256`, `order_signature_sha256`.

## Dataset creation

### Curation rationale

Natural-language reasoning benchmarks do not allow the computation and its surface form to be varied independently,
and they cannot guarantee that a test item is new. VarTrace gives exact control over both: which computations and
which name assignments occur in training, how often each family is seen, and which name assignments are held out.

### Source data

All problems are produced by a rule-based generator (task definition, exact solver and checker in pure Python).
The generator is deterministic: the same code and seeds reproduce every file byte for byte. `MANIFEST.json` lists
every file with its row count and SHA256.

### Annotations

There are no human annotations. Gold solutions and answers are computed by the exact solver.

### Personal and sensitive information

None. Variable names are synthetic three-letter strings.

## Considerations for using the data

- The problems are synthetic and narrow by design (arithmetic modulo 23 over a few variables). Results on VarTrace
  measure the tested behaviour in this controlled setting and do not by themselves establish it for natural text.
- G2 and the counterfactual probe are report-only panels. Use the `selection` config for any choice of
  hyperparameters.
- The frequency levels are a property of a schedule, not of a training row: use the schedules when the exposure
  count of a family matters.
